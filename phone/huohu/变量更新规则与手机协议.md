# 恋爱巴别塔 · 会话变量与手机协议

> 两部分：**A** 粘到角色卡「会话变量 → 更新规则」；**B** 新建一条世界书条目「手机协议」（常驻，不设关键词）。初始变量 JSON 见同目录 `state.json`。

---

## A. 变量更新规则（粘到「更新规则」栏）

每轮只写发生了变化的字段，未变化的字段不要重复输出。所有值必须是合法 JSON。

**time**
- `date`：剧情日期，格式 `2025.07.01`；跨天时更新。`week`：对应英文缩写 Mon～Sun，必须与日期一致。
- `slot`：当前时段，只能是 `早晨` / `白天` / `傍晚` / `夜晚` / `深夜` 之一。
- `clock`：剧情时间 `HH:MM`，24 小时制，随剧情推进更新。
- `weather`：只能从这些里选：`晴` / `酷热` / `多云` / `阴` / `小雨` / `大雨` / `雷阵雨` / `雪` / `雾`。手机的天气图标和主题色跟着它变。

**scene**
- `place`：当前具体地点，格式如 `锦绣云湾 2001 · 客厅`、`复旦大学 · 食堂`、`外滩`。
- `present`：当前场景里物理在场的女主槽位数组，如 `["h1","h4"]`；无人时 `[]`。

**girls.h1～h6**（槽位固定：h1 陈霜月、h2 江澜、h3 周莹春、h4 柳轻飏、h5 东方遇晓、h6 叶潇雨）
- `love`：0～100 整数。只能按选项三元律变动：直男选项 [-2, 0]，攻略选项 [+1, +2]，乐子人选项 [-3, +3]。每轮只改本轮互动涉及的人。
- `rel`：四字以内。随 love 阈值变化：0-29 陌生人/室友/冤家，30-59 朋友/熟人/在意，60-89 暧昧/知己/依恋，90-100 恋人（仅个人线）。
- `in`：该角色入住剧情完成时置 `true`，之后不再改。

**me**
- `visual`：主角当前生理状态，十字以内。`wear`：按时间地点换装。
- `inventory`：字符串数组，手机主屏的「背包」直接显示它。获得物品追加，消耗/送出/丢失移除。`智能手机` 和 `公寓钥匙` 必须始终存在。

**plot**
- `phase`：`common`（共通线）→ 全员入住后 `daily` → 进入个人线 `route` / 后宫线 `harem`。
- `events`：关键事件发生时追加事件名（事件名表见 B 末尾），只追加不删除。
- `tokens`：拿到某人信物时追加其槽位，如 `"h2"`。
- `badend`：每次进入 Bad End +1。`loop`：每次重开周目 +1。

**qq**（见 B 手机协议）
- `chats.hX`、`group`、`moments` 三类数组分别最多保留 15 / 20 / 10 条，超出时删最旧的。
- `unread`：有新消息时对应键 +1（私聊键为槽位 `h1`，群聊键为 `group`，动态键为 `moments`）；主角在剧情里看手机后清零。
- `call`：通话进行中写 `{"with":"h2","lines":["…"]}`，结束后写 `{}`。

## B. 世界书条目「手机协议」

```
<Phone_Protocol>
主角随身带着智能手机，玩家会通过手机界面做四种操作。玩家消息以下列前缀开头时，按对应规则处理，并把结果写进会话变量 qq。手机上的所有消息都是剧情的一部分，可以在正文里被提及、吐槽或忽略。

1. 私聊：消息以「（QQ·私聊 某人）」开头，后面是发送内容。
   - 把这条追加到 qq.chats.<她的槽位>，格式 {"s":"me","t":"内容","at":"HH:MM"}。
   - 由她的性格、好感、是否在线决定回不回、怎么回、回几条。回复追加为 {"s":"<槽位>","t":"…","at":"HH:MM"}。
   - 她不在线/在上课/在睡觉时可以不回或下一轮再回。如果她此刻就在主角身边，她可以当面吐槽。
   - 方言消息在 t 里直接附括号意译。

2. 群聊：消息以「（QQ·群聊）」开头。群名「锦绣云湾2001」，成员是已入住的女主和主角。
   - 追加到 qq.group，格式同上。按在线状态和性格决定谁接话，可以多人接、可以没人理、可以歪楼。

3. 发动态：消息以「（QQ·发动态）」开头。
   - 追加到 qq.moments：{"s":"me","t":"内容","img":"","at":"HH:MM","likes":[],"comments":[]}。
   - 由好感和性格决定谁点赞（likes 填槽位）、谁评论（comments 填 {"s":"h2","t":"…"}）。
   - 女主们也会主动发动态（晒饭、吐槽、直播预告、练舞视频），用同样格式追加，img 留空或填相册里已解锁 CG 的 id。

4. 视频通话：消息以「（QQ·视频通话 某人）」开头。
   - 若她接了：写 qq.call = {"with":"<槽位>","lines":["她说的每一句话"]}，正文正常演出通话；通话结束时把 qq.call 写回 {}。
   - 若她没接或挂断：qq.call 保持 {}，在她的私聊里追加一条她的消息说明原因。

5. 剧情内的手机消息：女主在剧情里主动给主角发消息、在群里说话、发动态时，同样写进对应数组，并把 qq.unread 对应键 +1。主角在剧情中看手机后把 qq.unread 清零。

6. 时间戳 at 用剧情时间，格式 "21:03"。

7. 前往角色剧情：消息以「（前往角色剧情 某人）」开头，表示玩家在手机上确认要进入她的个人线（她的好感已 ≥ 70）。按剧情配置表 Phase_2 处理：安排一个合适的独处场景，给出【A. 正式告白】/【B. 维持现状】的抉择，不要替玩家选。

关键事件：以下事件发生时，把事件名追加到 plot.events（只追加不删）：
jiang_movein 江澜入住｜dong_movein 东方遇晓入住｜ye_movein 叶潇雨入住｜liu_movein 柳轻飏入住｜zhou_movein 周莹春入住｜all_full 全员集齐
chen_confess / jiang_confess / zhou_confess / liu_confess / dong_confess / ye_confess 对应角色告白成功
dong_date_bund 和东方遇晓去外滩｜disney_date 去迪士尼约会（任意人）｜comicon_ye 陪叶潇雨去漫展
harem_true 真后宫线达成
</Phone_Protocol>
```

## C. 与现有组件的关系

现有三个 JSON 组件（`yuzu-mobile-hud` / `yuzu-dashboard` / `yuzu-status-bar`）暂时保留显示用途。改动两处即可避免数据打架：
1. 在「正文」条目里加一句：**h1～h6 的 love 与 rel 以会话变量为准，HUD 里的 h?_love / h?_rel 直接抄变量的值。**
2. 在「user状态栏」里加一句：**h?_state 与会话变量 scene.present 保持一致。**

以后若想把 HUD 的好感条改成读变量的变量组件，再另做。
